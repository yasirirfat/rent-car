# 2026-09-21 — Speedometer placement, blue-only palette, details header, performance

Four-part request: move the speedometer readout down, fix app lag, blue only,
and strip the details date chip to an icon next to the favourite.

## 1. Speedometer readout moved down

`lib/widgets/painters/speedometer.dart`, `_paintReadout`:

- Was `blockTop = center.dy - blockHeight / 2 + radius * 0.085` — the block
  *straddled* the dial centre, so the big number sat on top of the hub.
- Now anchored below the hub's lower edge (`hubBottom = center.dy + radius *
  0.155`), with a `radius * 0.045` gap, clamped so a tiny dial still fits:
  ```dart
  final blockTop = math.min(
    hubBottom + radius * 0.045,
    center.dy + radius * 0.68 - blockHeight,
  );
  ```
- `_paintCaption` now stacks directly under the readout band rather than at a
  fixed `0.735r`, so value / unit / caption read as one tight group.
- New public getters `readoutBand` and `valueTextRect` expose the measured
  geometry so the layout is assertable in tests.

## 2. Blue only

Two layers:

- **Speedometer** (`speedometer.dart`): tick redline `chrome` → `primary`;
  unit `secondary` (teal) → `primary`; needle counterweight `chrome` →
  `strokeStrong`; hub collar `strokeStrong` → `primary @0.35`; value arc no
  longer consults `gradientColors` at all. `shouldRepaint` dropped
  `gradientColors`, and `Speedometer` no longer forwards it.
- **Whole app** (`lib/core/app_color.dart`): `secondary` was retargeted from
  teal `#0FA396` to an **alias of `primary`**. That single change made ~100
  call sites blue without editing them. `secondaryDeep = primaryDeep`,
  `info = primary`, and `accentFor(index)` now just returns `primary` (it used
  to cycle blue/teal/amber, which is why the home cards each had a different
  hue).

`amber` (stars, prices), `success` (availability, compare winner) and `danger`
(favourite heart) are kept **for meaning only** — documented in `AppColor`.

Also flattened in `car_details_screen.dart`: the three `_RingStat` rings are
all `AppColor.primary` (Power was teal, Value amber); every `StatBar` accent is
primary; every `SpecTile` accent is primary; `ProgressRing` no longer lerps
toward `secondary`; gallery ring/counter use `primary`.

## 3. Details header — icon-only date control

`car_details_screen.dart`:

- The `_DateRangeChip` (~118 lines) was **deleted**. It rendered a calendar
  slot + "Add dates" / formatted range + a `{days}d` badge + an inline clear
  button — too wide for a header.
- Replaced by a bare `_RoundIconButton(icon: Icons.calendar_month_rounded)`
  placed immediately left of the favourite button, both at the right edge with
  a `Spacer()` pushing the back arrow to the left.
- `_RoundIconButton` gained an `active` flag: when a range is chosen the
  button tints blue (`primary @0.12` fill, `primary @0.45` border, blue icon),
  so the information the chip used to carry is still communicated. Wrapped in
  `AnimatedContainer(200ms)`.

## 4. Performance

Root cause was **not** the rendering — it was `AppStateScope`:

- `lib/core/app_state.dart` — `updateShouldNotify` returned `true`
  unconditionally. `InheritedNotifier` calls that on **every**
  `notifyListeners()`, so every favourite toggle, search keystroke and
  `markViewed` marked **every `AppState.of` caller dirty** — and since each tab
  is a direct `IndexedStack` child of `_MainWrapperState`, that rebuilt the
  whole app. Changed to `false`. The notifier is final, so the inherited value
  can never actually change; listeners still fire because the element
  subscribes to the `ChangeNotifier` independently of this method.

Three secondary wins:

- `lib/widgets/entrance_fade.dart` — the wrapper kept an `Opacity` (a
  `saveLayer` **per frame, per list item**) alive forever after the animation
  finished. Added a `_done` flag set on `AnimationStatus.completed`; `build`
  then returns the bare child.
- `lib/widgets/car_card.dart` / `home_screen.dart` /
  `car_details_screen.dart` — `Image.asset` had no `cacheWidth`, so every card,
  the hero and every gallery page decoded a **full-resolution PNG** and then
  downscaled it per frame while scrolling. Added `cacheWidth: maxWidth * 3` and
  dropped `FilterQuality.high` → `medium`.
- `speedometer.dart` — the value-arc glow blur went `12` → `6` radius and
  `0.20` → `0.16` alpha; it repaints on every animation frame of the 1.4s
  sweep, so it was the most expensive thing the gauge did.

## Bonus bug found by the new test

The new "tapping the calendar icon opens the range picker" test surfaced a
**pre-existing** `RenderFlex overflowed by 106 pixels` in the stock
`DateRangePickerDialog` header on a 400px viewport. Fixed in
`lib/car_data/custom_date_picker_dialoge.dart`:

- `insetPadding.horizontal` 28 → 12 (gives the picker more width).
- Added `rangePickerHeaderHeadlineStyle` (fontSize 15) and
  `rangePickerHeaderHelpStyle` (fontSize 10) — the defaults are sized for a
  tablet dialog.

## Tests

48 → **60**. New groups/changes:

- `Details screen date range` — rewritten: header is icon-only (no
  "Add dates" text), calendar and favourite are adjacent at the right edge,
  tapping the calendar opens the picker, and the performance dashboard uses
  blue only (walks every `ProgressRing` and `StatBar`).
- `Speedometer readout placement and colour` — 4 tests: readout sits below
  centre and clear of the hub; a longer value does not shift it vertically;
  `gradientColors` is ignored (asserted via `shouldRepaint` **and** by
  scanning rendered pixels for pink); the dial contains blue and zero
  teal/amber pixels. Uses a `_renderPainter` helper → `Picture.toImageSync` →
  `toByteData(rawRgba)`; note `dart:ui` has **no `Image.getPixel`**.
- `Performance guards` — `updateShouldNotify` is false; `EntranceFade` drops
  its `Opacity` once settled; the car image is wrapped in a `ResizeImage`
  (the observable proof `cacheWidth` was applied — `Image.cacheWidth` is not a
  public field).
- `Light theme tokens` — added "structural palette is blue only" and
  "semantic colours stay distinct from the accent blue".
